# Kongle @TAG@

This is the 0.4.0 development track. The current local build contains the new
watch UI and input flow; the sensor/media features below are release gates,
not claims about functionality already included in an early candidate.

- Black background, Catppuccin Mocha accents, 20 px text and titled panels.
- Compact clock date, optional unread bell and connected-only blue Bluetooth.
- Media to the right of the clock, notifications above it, home controls to
  the left and settings below. Double button press also opens Media.
- About shows firmware version, battery details and the actual advertised BLE MAC.
- English default with an initial Bokmål option and Latin-1 notification text.

Before publishing stable v0.4.0:

- [ ] Implement/test InfiniTime-compatible BLE media control and Furu's active
      Android player bridge, including previous/next semantics in Spotify and
      the maintainer's audiobook app, reconnect and missing-player handling.
- [ ] Implement/test heart-rate acquisition, stopping sensor/LED drive when not
      measuring, validity/age indication and power impact. Continuous HR is not
      implicitly enabled by displaying a clock field.
- [ ] Implement/test step measurement using the identified Bosch sensor variant
      and the [measurement plan](../design/step-counter-plan.md), including
      false positives, short walks, sleep, date/reset handling and Furu reads.
- [ ] Validate display readability, button double press/recovery hold, touch
      targets, brightness partial redraws and language/date fit on hardware.
- [ ] Validate OTA, unconfirmed trial rollback, explicit confirmation, BLE cache
      recovery/reconnect and notification delivery during normal daily use.
- [ ] Update this summary to describe the final shipped behavior and remaining
      limitations; collect daily-driver battery results before promotion.

RC tags use v0.4.0-rc.N on reviewed commits already merged to master, per the
existing release policy. Do not publish a stable tag while any required item
above remains incomplete. Keep experimental touch-to-wake out of release OTA.

Calendar via screen long press is a later feature: it requires a bounded Furu
agenda sync, timezone/date handling and a real touch-hold recognizer. It is not
part of the stable 0.4.0 requirements unless explicitly added to scope.
